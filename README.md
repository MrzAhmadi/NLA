# Natural Language Autoencoder — Qwen 2.5-0.5B

In this project, we implement a Natural Language Autoencoder (NLA) to verbalize and reconstruct the internal representations of a language model through a learned round-trip: activation → text → activation. This project is not limited to implementing an inference script but takes a step further by developing an automated pipeline to train, evaluate, and interactively inspect the learned representations.

The main goal of this project is to analyze the internal representations of a language model at specific token positions. To this end, a trained autoencoder is needed to convert activation vectors to text and back, so that the encoded information can be effectively studied.

At the end of the pipeline, an evaluation system assesses how closely the reconstructed activations match the original vectors and how well the verbalized descriptions capture what the model encodes.

---

## Model Choice

As a target model, Qwen 2.5-0.5B-Instruct is selected because of its compatibility with 8 GB of GPU memory and its clean residual stream architecture, which is straightforward to instrument with forward hooks. Qwen 2.5-0.5B-Instruct is the most accessible instruction-tuned model in this weight class, with standard grouped-query attention and a predictable 24-layer residual stream of dimension 896.

Activations are extracted at **layer 16 of 24**, which is approximately two-thirds through the model depth — deep enough to carry rich semantic content, shallow enough that the representation has not yet collapsed toward the output vocabulary.

---

## Architecture

In the NLA system, there is a dedicated component for each direction: the **Activation Verbalizer (AV)** converts an activation vector to text, and the **Activation Reconstructor (AR)** converts text back to an activation vector.

### Activation Verbalizer

The most important implementation detail is the injection mechanism: the embedding of a rare CJK character `㈎` (token id 149705) is replaced with the L2-normalized activation vector before the forward pass, scaled to `injection_scale = sqrt(896) ≈ 29.93`. This injection ensures that the generated description is conditioned solely on the target activation, and the model generates autoregressively from `inputs_embeds`. The full Qwen 0.5B model serves as the Activation Verbalizer, and all transformer weights are updated during training.

### Activation Reconstructor

The Activation Reconstructor consists of the first 12 layers of Qwen (frozen), followed by a single `Linear(896, 896, bias=False)` value head. The value head is initialized as an identity mapping — `nn.init.eye_(ar.value_head.weight)` — so the Activation Reconstructor starts by returning the last hidden state unchanged. In practice, this drops the initial reconstruction error from 1.94 to 1.61, giving the optimizer a better starting point.

## Training Pipeline

Manual inspection of language model internal states is a time-consuming and error-prone process. To organize the NLA system, two components must be integrated together, and the training procedure must coordinate all stages from supervised fine-tuning up to reinforcement learning.

The main objective of the pipeline is to take an input text corpus and run a series of actions in three stages to produce trained NLA components.

### Data

Running the full training pipeline on a dataset of token activations is time-consuming and resource-intensive, and for this reason, the pipeline is designed to be parameterized and controllable with respect to dataset size and training steps. The dataset consists of 5,000 token activations extracted from 300 Wikipedia paragraphs and 200 Alpaca instruction-response pairs. For each text, up to 10 positions are sampled with at least 10 tokens of left context.

For labeling, each activation is paired with a 2–3 sentence description generated by Qwen 0.5B itself, prompted with the token text, position, and surrounding context. Due to the use of the same model for labeling and subject, label quality is the primary bottleneck of this pipeline; the labeler generates generic descriptions, which is a known confounder for the supervised fine-tuning stages.

### Stage 1 — AR Supervised Fine-Tuning (100 steps, LR = 1e-4)

The value head is trained on (description, activation) pairs. The backbone is frozen throughout all training. The loss is MSE between the predicted and target activation vectors, both L2-normalized. Without this stage, the reinforcement learning signal is too noisy to learn from.

### Stage 2 — AV Supervised Fine-Tuning (100 steps, LR = 5e-6)

The Activation Verbalizer is trained to reproduce the reference descriptions, conditioned on the corresponding activation vectors via injection. The loss is masked cross-entropy over description tokens only. This is the imitation phase: the Activation Verbalizer learns the style of valid descriptions before reinforcement learning optimizes reconstruction quality.

### Stage 3 — Reinforcement Learning (300 steps, LR = 5e-6)

The reward is `cos_sim(AR(AV(activation)), activation)`, the round-trip fidelity. A log reward transformation is applied — `reward = log(1 + cos_sim)` — which compresses high rewards and amplifies the gradient signal when reconstruction quality is low. The algorithm is REINFORCE with an exponential-moving-average baseline (α = 0.9).

## Results

The results of this project demonstrate that the Activation Verbalizer has different behavior across different token types.

FVE is computed using the paper's formula: `FVE = 1 − ℒ / E[‖h − h̄‖²]`, where ℒ is mean per-dimension reconstruction MSE and the denominator is the variance of activations around their mean over the evaluation set.

| Metric | Result |
| --- | --- |
| cos_sim mean (all) | **0.555** |
| cos_sim (content tokens) | 0.536 |
| cos_sim (function tokens) | 0.578 |
| FVE (paper formula) | **−0.361** |
| Tokens above cos_sim 0.6 | **41%** |

Distribution of cos_sim across 200 evaluation examples (seed 42):

## Key Findings

At the end of this project, there are several key findings that can be highlighted.

### Function Words Reconstruct Better Than Content Words

Function tokens (cos_sim 0.578) reconstruct better than content tokens (cos_sim 0.536), which is the opposite of what the paper reports for large models. The negative FVE (−0.361) makes this concrete: the reconstruction is worse than predicting the mean activation, meaning the NLA has collapsed to outputting a single generic description regardless of input. The Best-5 results confirm this — all five top-scoring tokens are function words (`,`, `and`, `the`) and all five share the identical description *"The term 'concept' most closely relates to this activation vector..."*. The Activation Verbalizer learned one output that maps to the centroid, and the centroid is closest to function words because their activations cluster near the mean of the representation space. Cosine similarity hides this failure; FVE exposes it.

### Reward Hacking Under Reinforcement Learning

Another important finding is related to the training dynamics and reward optimization. The results of the study show that, without a strong regularization constraint, the Activation Verbalizer drifts into reward hacking: it generates token sequences that maximize the Activation Reconstructor's score without producing readable natural language. This failure mode does not appear in the original paper because their training uses a KL divergence penalty against a frozen reference policy; at 0.5B scale with self-generated labels, the reward signal is strong enough to override any implicit regularization from the supervised fine-tuning initialization.

### Qualitative Example

For the text *"The capital of Iran is Tehran."*, the Activation Verbalizer produces coherent and semantically accurate descriptions at named-entity positions:

**Token `Iran` (position 3, cos_sim 0.665):**
> *"The concept that is encoded by this activation vector 'Iran' is related to Iran's location and its political significance. This activation vector corresponds to the first element in the sequence of countries mentioned: 'Iran'. When such a vector appears, it indicates that currently, Iran is being referenced alongside other nations or regions within the given context."*

**Token `Tehra` (subword of "Tehran", cos_sim 0.634):**
> *"The activation vector 'Tehra' is most likely encoding the concept of 'Tehran' at this particular point. It could be decoding something related to information about Iran's capital city, possibly including details such as its location in the country, history, geography, culture, or politics surrounding it."*

## Why Results Differ From the Paper

This project has focused on training with self-generated labels from Qwen 0.5B. Despite the fact that self-labeling is the most accessible approach without external API credentials, the discovered bottleneck shows that label quality is the single most impactful factor for FVE, and not the subject model size.

| Factor | This project | Paper |
| --- | --- | --- |
| Subject model | Qwen 0.5B (896-dim) | Claude 3 (internal) |
| Labeler | Qwen 0.5B (self-labeling) | Claude API |
| RL algorithm | REINFORCE | GRPO |
| Training data | 5,000 samples | Millions |
| FVE | −0.361 | 0.60–0.80 |

The negative FVE shows that self-labeling at 0.5B scale causes full centroid collapse — the verbalizer outputs one generic description for all inputs, and the reconstructor maps it to the mean activation. The gap to the paper is therefore not primarily about model size; it is about label quality. With a stronger labeler (e.g. a larger model or the Claude API), the verbalizer would receive discriminative training signal and FVE would recover. GRPO would further help by stabilizing the RL phase without reward hacking.

## Interactive Interface

The Streamlit app ([app.py](app.py)) goes beyond the core NLA round-trip. Step 1.5 implements a **logit lens sweep**: for each of the 24 layers, the hidden state at the selected token position is projected through the final layer norm and unembedding matrix, showing which next-token prediction the model holds at each depth and at which layer that prediction stabilizes. Step 4 implements **causal steering**: after the verbalizer generates a description, the user can edit it, reconstruct a new activation from the edited text via the Activation Reconstructor, and inject that activation into the subject model at the original layer and position via a forward hook — the interface then shows the top-5 next-token predictions before and after the intervention side by side. This directly tests whether the Activation Reconstructor's learned mapping has causal influence over model behavior, which is the validation the paper describes in its intervention experiments.

```bash
python -m streamlit run app.py
```

## Reproducibility

All experiments were run on an RTX 3070 (8 GB VRAM), Intel Core i7-12700H, 32 GB DDR5. The full pipeline completes in under 40 minutes including dataset download.

```bash
pip install -r requirements.txt
./run.sh
```

Or step by step:

```bash
python pipeline/generate_data.py
python pipeline/generate_explanations.py
python pipeline/train.py
python pipeline/evaluate.py
python -m streamlit run app.py
```
