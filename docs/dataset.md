# Dataset Generation

This section discusses how to prepare the required dataset to run and evaluate the pipeline. Fundamentally, the pipeline requires a dataset of token activations and, after ending the training stage, it is required to compare generated descriptions with the original activation vectors.

---

## Activation Extraction — `pipeline/generate_data.py`

The most important part of gathering activations from a language model is the extraction process, which captures the hidden state at each token position to record what the model encodes at that point.

The subject model is **Qwen 2.5-0.5B-Instruct**. Exploring any language model has many aspects and ways; as a target model, Qwen 2.5-0.5B-Instruct is selected because of its compatibility with 8 GB of GPU memory and its clean residual stream architecture, which is straightforward to instrument with forward hooks.

Activations are extracted at **layer 16 of 24**, which is approximately two-thirds through the model depth. Due to the analysis on a large-scale dataset of text, dynamic extraction in this project is designed to run without human interaction, and it is programmed to perform specific tasks by scripting.

The data sources are:

- **300 Wikipedia paragraphs** — loaded from `wikimedia/wikipedia` via HuggingFace datasets
- **200 Alpaca instruction-response pairs** — loaded from `tatsu-lab/alpaca`

For each text, up to 10 token positions are sampled with a minimum of 10 tokens of left context, since positions with very short context produce degenerate activations. The result is **5,000 activation vectors**, each of dimension 896, saved to `artifacts/data/activations.pt`.

---

## Explanation Generation — `pipeline/generate_explanations.py`

Inherently, the raw captured activations are high-dimensional and difficult to interpret directly, and they require a processing step to generate natural language labels so that the training stages have a warm-start signal.

For each activation, the model is prompted with the token text, its position, and the surrounding left context, and it is asked to describe in two to three sentences what concepts the model is most likely encoding at that position.

The labeler model is **Qwen 2.5-0.5B-Instruct**, which is the same model used as the subject. Due to the use of the same model for labeling and inference, label quality is the primary bottleneck of this pipeline; the labeler generates generic descriptions that are shorter and less semantically precise than descriptions generated by a larger external model, which is a known confounder for the supervised fine-tuning stages.

The generation uses greedy decoding (`do_sample=False`) with a maximum of 100 new tokens per example. Processing is done in **batches of 32** to fully utilize the available GPU, reducing generation time from several hours to approximately 15 minutes on an RTX 3070. The results are saved to `artifacts/data/explanations.pt`.

## Dataset Summary

| Property | Value |
|----------|-------|
| Subject model | Qwen 2.5-0.5B-Instruct |
| Extraction layer | 16 / 24 |
| Activation dimension | 896 |
| Total examples | 5,000 |
| Text sources | Wikipedia + Alpaca |
| Labeler model | Qwen 2.5-0.5B-Instruct |
